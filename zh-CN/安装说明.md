## 用法 A：用官方预编译安装包（改 .qm 即可）

把 `deskflow_zh_CN.qm` 放进 Deskflow 的 `translations` 目录。程序按以下顺序查找，**命中第一个非空目录就停止**：

1. `<程序目录>/translations/`
2. `<程序目录>/../translations/`
3. `<程序目录>/../Resources/translations/`  ← macOS 应用包用这个
4. `<程序目录>/../share/deskflow/translations/`
5. `~/.local/share/deskflow/translations/`
6. `/usr/local/share/deskflow/translations/`
7. `/usr/share/deskflow/translations/`

具体路径：

- **macOS**：`/Applications/Deskflow.app/Contents/Resources/translations/deskflow_zh_CN.qm`
- **Windows**：`C:\Program Files\Deskflow\translations\deskflow_zh_CN.qm`
- **Linux**：`/usr/share/deskflow/translations/deskflow_zh_CN.qm`

### 还需要 Qt 自带的中文翻译

对话框上的「确定 / 取消 / 是 / 否」这类标准按钮由 **Qt 自己的语言包**翻译，Deskflow 会去找 `qt_zh_CN.qm`（注意中文用的是完整语言码 `zh_CN`，不是 `zh`）。

把 Qt 的 `qtbase_zh_CN.qm` 复制过去并改名为 `qt_zh_CN.qm`，放在与 `deskflow_zh_CN.qm` 同一层级、或上述任一 `qt`/`qt6` 目录即可：

```bash
# macOS 示例
cp /path/to/Qt/translations/qtbase_zh_CN.qm \
   /Applications/Deskflow.app/Contents/Resources/translations/qt_zh_CN.qm
```

如果找不到它，界面主体仍是中文，只有标准按钮会保留英文。

### 启用中文

打开 Deskflow → 设置 → **Language** 下拉框选「简体中文」→ 保存。
（默认是「跟随系统」：`I18N` 会用 `QLocale()` 自动匹配，系统语言是中文时开箱即中文。）

## 用法 B：从源码编译

仓库里 `translations/deskflow_zh_CN.ts` 已经是完整中文版，直接按正常流程构建即可：

```bash
cmake -S . -B build -DCMAKE_INSTALL_PREFIX=<安装前缀>
cmake --build build
```

构建时 `qt_create_translation()` 会自动调用 `lupdate` + `lrelease` 生成 `.qm`；macOS 应用包还会把 Qt 的 `qtbase_zh_CN.qm` 一并拷进 bundle。

> 若要单独重新编译语言包（需 Qt Linguist 工具）：
> ```bash
> lrelease translations/deskflow_zh_CN.ts -qm deskflow_zh_CN.qm
> ```
> 没有 Qt 环境的话，`pip install PySide6-Essentials` 也会带上 `pyside6-lrelease`。

## 仍未汉化的部分（有意保留）

1. **运行日志内容**。核心进程里数百条 `LOG_INFO` / `LOG_DEBUG` 等日志字符串是 C++ 硬编码的英文，不属于 Qt 翻译体系。日志保留英文更利于在 GitHub 提 issue 时被搜到。需要的话可以另开一轮处理。
2. **帮助文档正文**。帮助窗口加载的是 `docs/HelpMain.md`（24 行 Markdown），程序把文件名写死了，改成中文会让英文用户失去英文帮助，所以没动。
3. **配置文件的选项名**。如 `halfDuplexCapsLock`、`switchDelay`、`section: links` 这类是配置语法，不是界面文案。
4. **Deskflow** 产品名本身。
